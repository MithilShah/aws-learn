So far each rule has stood on its own, in one account and one Region. This step scales up: bundle
many rules into a **conformance pack** you deploy as one unit, and roll up results across many
accounts and Regions into one read-only view with an **aggregator**.

## Conformance packs: rules bundled as one

A conformance pack is a collection of AWS Config rules *and* remediation actions that you deploy
as a single entity — in one account and Region, or across an organization in AWS Organizations.
You create a pack by authoring a **YAML template** listing the managed or custom rules (and
remediation) it contains.

A pack template reads much like this — a list of rules under `Resources`:

```yaml
Resources:
  S3BucketPublicReadProhibited:
    Type: AWS::Config::ConfigRule
    Properties:
      ConfigRuleName: s3-bucket-public-read-prohibited
      Source:
        Owner: AWS
        SourceIdentifier: S3_BUCKET_PUBLIC_READ_PROHIBITED
  EncryptedVolumes:
    Type: AWS::Config::ConfigRule
    Properties:
      ConfigRuleName: encrypted-volumes
      Source:
        Owner: AWS
        SourceIdentifier: ENCRYPTED_VOLUMES
```

<Callout type="tip">
You don't have to start from a blank file. AWS provides sample conformance pack templates you can
deploy to evaluate your environment quickly, and you can build a custom pack from there.
</Callout>

## Aggregators: one read-only view across accounts and Regions

A single pack still reports per account and Region. An **aggregator** is the piece that brings
everything together: it collects AWS Config configuration and compliance data into one
*aggregator account* so a central team can see the whole estate at once.

An aggregator can pull from accounts and Regions you name individually, or from an entire
organization. That choice changes one thing — whether you need to authorize each source account.

<Callout type="misconception">
An aggregator is **read-only**. It replicates data from the source accounts into the aggregator
account for viewing — it gives you no mutating access to the sources. You can't deploy rules or
push snapshot files to a source account through an aggregator. And using aggregators **incurs no
additional cost**.
</Callout>

## When you'd use each

A central IT team working across accounts typically uses both together: deploy a conformance pack
across the organization so every account is checked against the same rules, then create an
aggregator so the team sees all of that compliance data in one read-only dashboard.

## Key terms

<KeyTerms>
  <Term name="Conformance pack">A collection of AWS Config rules and remediation actions deployed as a single entity, in an account and Region or across an organization.</Term>
  <Term name="YAML template">The file that defines a conformance pack by listing its managed or custom rules and remediation actions.</Term>
  <Term name="Aggregator">An AWS Config resource that collects configuration and compliance data from multiple accounts and Regions into one aggregator account, as a read-only view, at no additional cost.</Term>
  <Term name="Source account">An account whose AWS Config data an aggregator collects — named individually or drawn from an organization.</Term>
  <Term name="Authorization">The permission a source account grants an aggregator to collect its data. Not required when the sources belong to the same organization in AWS Organizations.</Term>
</KeyTerms>
