Not all data is read equally often. A website's logo is served constantly; last year's tax
records almost never. Amazon S3 lets you store each object in a **storage class** suited to how
you use it, trading cost against how quickly and how often you need the data back.

## One durability, different availability and cost

Here's the key thing to understand first: every S3 storage class is designed for the same very
high **durability** — 99.999999999% (eleven nines), meaning S3 is built not to lose your objects.
What changes between classes is **availability**, **retrieval speed** and **price**, not whether
your data is safe.

Most classes store your data redundantly across at least three Availability Zones. The one
exception is **S3 One Zone-IA**, which uses a single Availability Zone to cost less — so it's
designed for the same durability within that zone, but the data is lost if that one zone is
destroyed. That's the trade you're making when you choose it.

<Callout type="note">
Durability (will my data survive?) and availability (can I get to it right now?) are different
promises. All S3 classes aim for the same eleven-nines durability. One Zone-IA lowers cost by
lowering resilience to the loss of a whole Availability Zone, not by lowering durability within
one.
</Callout>

## The classes, from hottest to coldest

The general purpose storage classes line up roughly by how "warm" the data is:

- **S3 Standard** — frequently accessed data, millisecond access. The default.
- **S3 Intelligent-Tiering** — for data whose access pattern you don't know or that changes. S3
  automatically moves each object between frequent and infrequent tiers based on use, so you don't
  have to guess.
- **S3 Standard-IA** (Infrequent Access) — data you read rarely but need instantly when you do,
  stored across multiple Availability Zones.
- **S3 One Zone-IA** — like Standard-IA but in a single Availability Zone, for a lower price when
  you can tolerate that reduced resilience (for example, data you could regenerate).
- **S3 Glacier Instant Retrieval** — archive data that's almost never read but must come back in
  milliseconds when it is.
- **S3 Glacier Flexible Retrieval** — archive data where waiting minutes to hours for retrieval is
  acceptable.
- **S3 Glacier Deep Archive** — the lowest-cost class, for long-term archives you retrieve in
  hours.

## Moving objects between classes with lifecycle rules

You rarely want to pick a class once and leave it forever. Data cools down: today's active log
file is next quarter's archive. A **lifecycle rule** automates that journey — it tells S3 to
**transition** objects to a cheaper class, or **expire** (delete) them, on a schedule you set,
usually matched to a key prefix.

<Callout type="tip">
Transitions generally move data one way — from warmer to cooler classes — so model your lifecycle
rules around how data actually ages. Pair them with sensible key prefixes (for example
`logs/2026/…`) so a rule can target exactly the objects you mean.
</Callout>

## Key terms

<KeyTerms>
  <Term name="Storage class">A storage tier for an object that trades cost against availability and retrieval speed. All classes aim for the same eleven-nines durability.</Term>
  <Term name="Durability">How safe stored data is from loss. Every S3 storage class is designed for 99.999999999% (eleven nines) durability.</Term>
  <Term name="Availability">How readily you can retrieve data when you ask for it — distinct from durability, and where classes differ.</Term>
  <Term name="S3 Intelligent-Tiering">A class that automatically moves objects between access tiers based on usage, for data with unknown or changing access patterns.</Term>
  <Term name="Lifecycle rule">A rule that automatically transitions objects to another storage class or expires (deletes) them on a schedule.</Term>
</KeyTerms>
